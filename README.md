# PHP 滑动验证码

一个基于 **PHP + GD + Redis** 实现的服务端滑动拼图验证码。

本项目的核心特点是：验证码不是简单地判断"滑块最终移动了多少像素"，而是同时校验
**验证码会话、滑块身份、拼图位置、滑动轨迹、移动时间/行为特征以及失败次数**，并使用
Redis 保存短生命周期的挑战数据。

> 当前 README 根据项目中的 `CaptchaController`
> 实现整理。项目代码依赖现有项目中的
> `BaseController`、`VisitorIdentity`、`CaptchaTrackValidator`
> 等组件，因此建议将本验证码作为现有 PHP 项目中的一个模块使用。

------------------------------------------------------------------------

## ✨ 功能特点

-   动态生成滑动拼图验证码
-   320 × 160 验证码画布
-   48 × 48 滑块
-   每次随机生成多个候选滑块
-   支持多种几何形状
-   支持圆形、矩形、三角形、多边形、星形、心形、椭圆、菱形等形状
-   随机生成真实目标槽位
-   真实滑块与目标槽位使用一致的形状、比例和坐标关系
-   背景随机纹理
-   波浪扭曲
-   干扰线
-   干扰点
-   干扰弧线
-   九宫格背景碎片
-   Redis 保存验证码状态
-   验证码 180 秒自动过期
-   防止同一访客高频刷新
-   防止同一 IP 创建过多不同访客身份
-   支持失败次数统计
-   连续失败达到阈值后自动安全锁定
-   验证成功后立即删除验证码缓存，降低重复使用风险
-   服务端进行绝对坐标二次校验
-   服务端进行滑动轨迹行为分析
-   使用一次性 ticket 作为验证成功凭证

## 🧩 验证码工作原理

整个流程可以分成：

``` text
客户端请求验证码
        │
        ▼
服务端验证访客身份
        │
        ▼
Redis 访问频率检查
        │
        ▼
随机生成验证码规则
        │
        ├── 随机真实滑块
        ├── 随机目标位置
        ├── 随机形状
        ├── 随机缩放比例
        └── 随机背景规则
        │
        ▼
GD 生成验证码图片
        │
        ├── 背景纹理
        ├── 形状凹槽
        ├── 波浪扭曲
        ├── 干扰线
        ├── 干扰点
        └── 九宫格切片
        │
        ▼
Redis 保存验证码核心状态
        │
        ▼
返回前端
        │
        ▼
用户拖动滑块
        │
        ▼
提交：
x + token + select_idx + select_key + track
        │
        ▼
服务端验证
        │
        ├── VisitorIdentity
        ├── Token
        ├── 滑块身份
        ├── 真实索引
        ├── 滑动轨迹
        └── 最终坐标
        │
        ▼
验证成功
        │
        ▼
返回 ticket
```

# 🛡️ 服务端验证机制

验证码验证不是单一条件判断，而是多层校验。

## 1. 访客身份校验

服务端通过：

``` php
VisitorIdentity::cookieName()
```

获取访客 Cookie。

然后调用：

``` php
VisitorIdentity::verify($visitorId)
```

检查访客身份是否合法。

如果不存在或无效：

``` json
{
    "code": 429,
    "msg": "访问身份缺失或无效"
}
```

------------------------------------------------------------------------

## 2. Token 校验

验证码生成时会生成：

``` php
$serverToken = hash_hmac(
    'sha256',
    $visitorSubject . '-' . getTimestamp(),
    $secretKey
);
```

验证时使用：

``` php
hash_equals(
    $captchaData['token'],
    $clientToken
)
```

进行比较。

这样可以避免只依靠前端传递坐标进行验证。

------------------------------------------------------------------------

## 3. 滑块身份校验

每一个候选滑块都会生成独立 Key。

服务端会检查：

``` php
$selectKey
```

是否存在于当前验证码对应的滑块列表。

同时检查：

``` php
$select_idx
```

是否对应真实滑块。

因此攻击者不能只提交一个正确的坐标而跳过滑块选择。

------------------------------------------------------------------------

## 4. 绝对坐标校验

服务端保存：

``` text
init_x
init_y
target_x
target_y
```

用户最终移动距离：

``` php
$finalUserX = $initX + $userMoveDelta;
```

然后进行：

``` php
abs($finalUserX - $targetX) <= 6
```

判断。

当前代码默认 X 方向容差：

``` text
6 像素
```

------------------------------------------------------------------------

# 🧠 滑动轨迹验证

项目引入：

``` php
CaptchaTrackValidator
```

进行行为轨迹分析。

核心调用：

``` php
$validationResult = CaptchaTrackValidator::validate(
    $track,
    $targetX,
    $targetY,
    $initX,
    $initY,
    [
        'target_tolerance_x' => 6.0,
        'target_tolerance_y' => 20.0,
        'risk_threshold' => 60,
    ]
);
```

当前验证码控制器设置：

  参数                     当前值 说明
  ---------------------- -------- ----------------
  `target_tolerance_x`        `6` X 坐标允许误差
  `target_tolerance_y`       `20` Y 坐标允许误差
  `risk_threshold`           `60` 风险阈值

因此前端不应该只提交：

``` text
最终 x
```

而应该记录完整拖动轨迹：

``` text
x
y
t
```

其中：

-   `x`：当前滑块 X 坐标
-   `y`：当前滑块 Y 坐标
-   `t`：当前时间点或相对耗时

# 🌊 波浪扭曲

背景会经过：

``` php
applyWaveDistortion()
```

处理。

核心使用正弦和余弦计算像素偏移：

``` php
$offset = (int)(
    sin(($y / $period) + $phase) * $amplitude
    + cos($x / ($period * 1.5)) * ($amplitude / 2)
);
```

这样可以让背景纹理产生轻微非线性变化。

# 🔐 Redis 数据

验证码主要使用以下 Redis Key。

## IP 访问记录

``` text
captcha_visitor_limit_{md5(ip)}
```

用于限制同一个 IP 在短时间内创建大量不同访客身份。

当前有效期：

``` text
60 秒
```

------------------------------------------------------------------------

## 刷新频率限制

``` text
captcha_rate_limit_{visitorSubject}
```

当前使用 NX + EX 机制限制高频刷新。

当前有效期：

``` text
3 秒
```

------------------------------------------------------------------------

## 安全锁

``` text
captcha_lock_{visitorSubject}
```

用于连续验证失败后的临时锁定。

当前锁定：

``` text
15 分钟
```

------------------------------------------------------------------------

## 验证码核心数据

``` text
captcha_cache_{visitorSubject}
```

保存：

``` json
{
    "token": "...",
    "init_x": 20,
    "init_y": 50,
    "target_x": 230,
    "target_y": 50,
    "real_idx": 1,
    "rule_type": 2
}
```

有效期：

``` text
180 秒
```

------------------------------------------------------------------------

## 滑块映射

``` text
captcha_blocks_{visitorSubject}
```

保存候选滑块与真实滑块之间的映射关系。

有效期：

``` text
180 秒
```

------------------------------------------------------------------------

## 失败次数

``` text
captcha_fail_count_{visitorSubject}
```

失败次数有效期：

``` text
600 秒
```

也就是：

``` text
10 分钟
```

# 🚫 防刷策略

验证码生成接口并不是无限开放的。

### IP 级限制

同一 IP 在短时间内使用过多不同访客身份时：

``` text
429
刷新过于频繁，请稍后再试
```

### 用户级刷新限制

验证码刷新使用 Redis NX 锁。

当前：

``` text
3 秒
```

内不能重复生成。

### 连续验证失败限制

验证失败会：

``` php
$redis->incr($failCountKey);
```

当失败次数达到：

``` text
5 次
```

触发：

``` text
15 分钟
```

安全锁。

------------------------------------------------------------------------

# ♻️ 防重复验证

验证码验证开始后，服务端会立即删除：

``` text
captcha_cache_{visitorSubject}
captcha_blocks_{visitorSubject}
```

即：

``` php
$this->redis->del($captchaCacheKey);
$this->redis->del($captchaBlocksKey);
```

因此同一个验证码不能被正常重复提交。

# ⚠️ 安全说明

本项目是一个**行为验证码组件**，不能把滑动验证码单独视为完整的反自动化安全方案。

实际生产环境建议同时使用：

-   HTTPS
-   Cookie 安全属性
-   CSRF 防护
-   登录接口限流
-   IP / ASN 风险控制
-   设备或会话风险控制
-   Redis 原子操作
-   ticket 服务端绑定
-   ticket 短时有效
-   ticket 一次性消费
-   关键业务接口服务端鉴权
-   日志与异常行为监控

特别是验证码通过后返回的：

``` text
ticket
```

建议在真实业务中进一步绑定：

``` text
visitorSubject
业务接口
业务场景
创建时间
过期时间
```

并设置一次性消费机制。

# 🔌 前端提交建议

前端拖动时建议持续记录：

``` javascript
const track = [];

function recordTrack(x, y, startTime) {
    track.push({
        x: x,
        y: y,
        t: Date.now() - startTime
    });
}
```

最终提交：

``` javascript
const data = {
    x: finalX - initX,
    token: token,
    select_idx: selectIdx,
    select_key: selectKey,
    track: track
};
```

不要只记录最终位置。
